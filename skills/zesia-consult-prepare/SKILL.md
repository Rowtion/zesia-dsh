# zesia-consult-prepare

Prepare the current decision for 则灵; do not hand off ownership of the user's task. When invoked via `/zesia "<uuid>"`, the quoted UUID is the host assistant reply ID to review (not a `draftId`).

1. Identify the user's goal (to place in `context.goal`), the exact question and response to review, current approach, failed attempts and unresolved issue. Preserve explicit user constraints; keep agent inferences separate.
2. Build `context.statements`: stable id, kind, origin, text, sourceRef and sourceQuote. Copy user quotes exactly. Use actual visible message IDs or tool-result references; say `unavailable` when absent. Leave duplicated legacy facts/constraints/assumptions empty. Confirmation is permission to transmit, not verification of facts.
3. Select necessary original evidence. For engineering use `references/evidence.md`; other domains need the actual experiment, data definitions, units, methods or source passages relevant to this decision. Do not force Git fields onto non-code tasks. A local path/URL is only a locator: include the excerpt itself for the cloud. Preserve errors, numbers and code verbatim; label summaries as summaries. Use `evidenceFiles` for bounded local-file excerpts and `attachmentFiles` for screenshots, images, or documents (png, jpg, webp, gif, pdf, txt, md, json; up to 10 files and 6 MiB total). **All `evidenceFiles` and `attachmentFiles` paths must stay inside the current project workspace**: if you capture or compress temporary screenshots, save them inside the project directory (for example `.zesia/review/`), never in `/tmp` or outside the project root. Never send credentials, unrelated files, full chat history or hidden reasoning.
4. Call `zesia_consult` once with only the documented top-level keys (`brief`, `project`, `context`, and optional `requireMaterials`, `evidenceFiles`, `attachmentFiles`). Put `goal` inside `context.goal` and inline excerpts inside `context.materials`; never pass `goal` or `materials` at the top level, and omit `context.originalReply` or `context.goal` when empty instead of sending blank strings. For a document, deck or artifact review set `requireMaterials: true`. It prepares a local draft and opens the shared `https://zesia.dev/consult` online review window; finish briefly pointing to that window without pasting the packet into chat, then call `zesia_consult_wait` (or `zesia_consult_result`) with `draftId` to retrieve the opinion. Never self-approve or prepare duplicate drafts.
5. On response, load `zesia-consult-evidence` for evidence requests, `zesia-consult-decision` for user choices or unclassified clarification, and `zesia-consult-adopt` for checking usable advice. A cloud question grants no new local execution permission.
